Em resumo

O que foi feito

  • Baixamos da API do IBGE 639 respostas (543.652 valores), de mai/2000 a set/2026, e guardamos como vieram.
  • Montamos a lista de categorias das 4 tabelas (1.951 linhas), com a hierarquia tirada do código IBGE.
  • Juntamos os valores das 4 tabelas num só fato (153.741 linhas), ligados à categoria certa pelo par tabela e id.
  • Conferimos tudo com 15 validações (15 ok) e documentamos 20 exceções explicadas.
  • Ainda não calculamos nenhuma inflação: todos os números do fato são oficiais. Os cálculos feitos até agora servem só para conferir.

Linha do tempo das tabelas

O IBGE publica o IPCA-15 numa tabela nova a cada troca da estrutura de pesos (POF). As tabelas de dados se sucedem mês a mês, sem lacuna. A tabela 3065 traz só o índice geral, do início ao fim, e serve de gabarito.

Como as tabelas se juntam

Cada categoria tem dois identificadores. O código IBGE (ex.: 1111004) diz a posição na árvore. O id SIDRA (ex.: 12393) diz qual definição da categoria vale naquela tabela. Quando o IBGE reformula uma categoria, mantém o código e cria um id novo. Isso aconteceu em 87 códigos (84 subitem, 2 item, 1 subgrupo).

Por isso o fato liga cada valor à categoria pelo par (tabela, id SIDRA). Ligar só pelo código misturaria produtos diferentes, como mostram os exemplos.

Como manter esta página certa

Esta página é gerada pelo código a partir dos dados do repositório. Ninguém a edita à mão. Para atualizar:

uv run python -m macroaf.extract.atualizar
uv run python -m macroaf.transform.ipca15
uv run python -m macroaf.validate.ipca15
uv run python -m macroaf.relatorios.transformacoes --indice ipca15

Um teste regera a página e falha se o arquivo do repositório estiver diferente. Toda etapa que muda uma transformação regera a página no mesmo PR. Um índice novo ganha a sua página com --indice.

Degraus de explicação usados aqui: texto claro (resumo), diagramas (fluxo e linha do tempo) e página interativa. O degrau de vídeo ainda não foi feito.
